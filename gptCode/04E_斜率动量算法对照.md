## 一、核心结论

微信三因子文章对应的PTrade、QMT和聚宽代码，以及单因子`ETF动量轮动.py`，斜率因子公式相同：

```text
取最近25个收盘价P_t
y_t = P_t / P_0
y_t = alpha + beta * t + error_t          # 等权OLS，包含截距
R2 = sklearn LinearRegression.score(x, y)
slope_score = 10000 * beta * R2
```

因此它们与“OLS斜率乘R2”是同一种具体实现。四份代码的差别主要在平台、候选池、多因子融合和下单方式，不在斜率计算本身。

此前七星、五福、D3QN、四方和Huber文章仍属于斜率动量家族，但输入价格、回归权重和得分变换不同，数值及排名都可能不同。

七星和五福代码都不能直接作为标准WLS基准，但问题并不相同：

- 七星通用`_wls_fit`先计算`wx=w*(x-x_bar)`与`wy=w*(y-y_bar)`，再用`sum(wx*wy)`作斜率分子，因此分子实际是`w^2`，分母却是`w`；R2继续使用`w`。当权重不全为1时，这不是标准WLS。四方子策略传入全1权重，不受这个问题影响，仍等价于OLS；
- 五福斜率显式使用`W=weights^2`，但残差平方和使用`weights`，总平方和还围绕非加权均值计算，斜率与R2也不是同一权重口径。

## 三、数学差异

### 3.1 标准化原价格与对数价格

标准化原价格：

```text
y_t = P_t / P_0
```

- 消除了不同ETF价格水平的量纲；
- 对小幅收益，斜率近似每日算术收益；
- 固定百分比复利增长在原价格空间是曲线，强趋势时R2可能受到价格曲率影响。

对数价格：

```text
y_t = ln(P_t)
```

- 同样不受价格绝对水平影响；
- 固定百分比增长在log空间接近直线；
- 上涨与下跌在复利意义上更对称，斜率近似每日连续复利收益。

当日收益很小时两者近似；出现大幅上涨、下跌或窗口较长时，两者会产生不同斜率和R2。

### 3.2 `beta`与年化斜率收益

以下两种得分不是简单倍数关系：

```text
score_linear = beta * R2
score_annualized = (exp(250 * beta) - 1) * R2
```

年化变换对`beta`是非线性的。只有各资产R2完全相同时，两者的排序才必然一致；R2不同时，年化变换会更偏向陡峭斜率，并可能改变Top1。

`10000`只是正比例缩放，不改变单因子排名；对该因子再做横截面Z-Score时也会被抵消。

### 3.3 OLS与近期加权WLS

- OLS给窗口内每个价格点相同权重；
- WLS提高近期点权重，反应更快，但更容易受窗口末端噪声影响；
- 标准WLS若设权重从1升到2，最后一点在目标函数中的权重是第一点的2倍；
- 五福拟合实际使用平方权重，最后一点在斜率拟合目标中的名义权重是第一点的4倍；
- 七星当前代码由于斜率分子误用了`w^2`、分母使用`w`，无法用一个统一的“最后一点权重倍数”解释。

WLS不是OLS的纯性能优化，而是改变了经济假设，必须作为独立信号版本验证。

标准WLS应统一使用同一组权重：

```text
x_bar = sum(w*x) / sum(w)
y_bar = sum(w*y) / sum(w)
beta = sum(w*(x-x_bar)*(y-y_bar)) / sum(w*(x-x_bar)^2)
R2 = 1 - sum(w*(y-y_hat)^2) / sum(w*(y-y_bar)^2)
```

后续若测试近期加权版本，应重新实现上述标准公式，不能把七星或五福的现有数值结果当作标准WLS结果。

### 3.4 点数与收益间隔

25个价格点只有24个相邻收益间隔；26个价格点才覆盖25个间隔。当前M0的“126日收益”使用127个价格点，因此M3A也固定使用127点，避免因子替换时顺带改变实际回望长度。

### 3.5 R2的含义

R2只表示过去价格路径与拟合直线的吻合度，不是趋势未来延续概率，也不是风险调整收益。高R2可能来自平稳下跌；因此必须保留斜率符号，并用未来21日标签独立评价确认正确率。

## 四、多因子与换仓层不是斜率算法

三因子版本的完整排序是：

```text
z_bias = ZScore(bias_momentum across ETFs)
z_slope = ZScore(slope_score across ETFs)
z_efficiency = ZScore(efficiency_score across ETFs)
combined = 0.3*z_bias + 0.3*z_slope + 0.4*z_efficiency
```

这改变的是因子融合，不是斜率本身。横截面只有4只ETF时，均值和标准差容易被单只极端标的支配，某只ETF缺失还会改变全部ETF的Z-Score。

三因子代码又把当前持仓的综合分乘以`1.5`：

```text
final_score = combined_score * 1.5       # 当前持仓
```

当`combined_score < 0`时，乘1.5会让得分更负，反而更容易卖出，不是稳定的换仓保护。正确的滞回应比较挑战者与持仓的无量纲得分差，而不是直接做倍率乘法。

单因子`ETF动量轮动.py`使用固定得分差`0.001`，该阈值依赖因子量纲；若改用log斜率、年化斜率或Z-Score，阈值含义都会改变。

## 五、研究决定

1. M3A保持当前预注册定义：127个前复权收盘价、log价格、等权OLS、标准R2、`beta*R2`、月末信号；
2. 文章原版“25点标准化价格OLS”只作为独立复现版本，不与M3A同时改变回望周期和调仓频率；
3. 若M3A证明斜率家族有增量，再单独比较标准化原价格与log价格；
4. WLS必须另建版本，权重和加权R2使用同一口径；
5. 年化斜率变换不默认加入，必须证明其非线性放大带来样本外增量；
6. Huber只在OLS基准有效后测试，并在运行前冻结`epsilon`、正则项和拟合质量定义；
7. 三因子融合必须等待至少两个单因子独立通过，不直接采用文章遍历得到的`0.3/0.3/0.4`；
8. 所有版本保持同一候选池、成本、执行、未来标签和验收门槛，禁止用文章中的事后候选池收益替代因子检验。
