# 步骤02：聚宽数据范围与ETF候选池规则

## 状态

- 当前状态：已确认并冻结（v0.7-datafix1）
- 当前版本：v0.7-datafix1
- 前置步骤：步骤00、步骤01均已冻结
- 下一步骤：`03_回测引擎正确性验证.md`
- 本步骤只定义研究范围和数据合同，不下载数据、不运行回测、不评价收益

## 本步骤目标

预先限定ETF轮动策略允许使用的资产范围、历史代理范围、聚宽取数接口和动态准入规则，防止看到回测结果后手工增加赢家、删除输家或倒填尚未上市的ETF。

本步骤通过只表示“研究边界已经明确”，不表示数据质量已经验证，也不表示策略有效。实际取数、字段检查和回测均在聚宽环境中执行。

## 一、数据源边界

1. 策略研究和回测的行情、证券元数据及交易日历统一使用聚宽数据。
2. 本版本不使用东方财富、新浪、Yahoo、FRED或其他外部行情拼接训练历史。
3. 不把本地已有CSV作为正式输入；本地文件只能用于开发参考，不能进入正式聚宽回测结果。
4. 聚宽缺少某类历史数据时，缩短该袖套的起点或把该资产放入扩展层，不从外部补一条事后表现更好的序列。
5. 聚宽数据的实际最早日期、缺失率和可用代码由下一步骤在平台内查询并记录，本步骤不预先虚构日期。

## 二、核心资产范围

核心基线参考全天候框架覆盖四类宏观风险来源，但不采用桥水的专有权重，也不预设固定资产权重。

| 资产袖套 | 核心基线允许范围 | ETF交易层允许范围 | 暂不纳入核心基线 |
|---|---|---|---|
| 权益 | A股代表性宽基指数 | 跟踪A股宽基指数的非杠杆ETF | 行业、主题、单一风格、增强、红利、低波、海外单一国家ETF |
| 名义政府债券 | 中国国债总收益或财富指数，优先中长久期 | 国债ETF；若无合格国债ETF则该袖套暂不交易 | 信用债、可转债、城投债、公司债、政策性金融债 |
| 抗通胀实物资产 | 聚宽可获得的人民币黄金现货、黄金指数或可复现的黄金连续序列 | 境内实物黄金ETF | 黄金股、资源股、单一商品期货ETF、未经验证的广义商品拼接序列 |
| 流动性资产 | 现金、货币市场收益或短久期国债代理 | 货币ETF或短久期国债ETF | 中长久期债券、信用债、回购加杠杆 |

四类袖套都必须保留。不能为了把训练起点提前而删除某个袖套，也不能因为某个袖套历史收益低而将其移出候选范围。

### 2.3 备用ETF与替换边界

备用ETF不参与大类资产排名，只在主ETF因停牌、退市或历史数据不可用而无法代表该袖套时按事前顺序接替：

| 袖套 | 备用顺序 | 约束 |
|---|---|---|
| 权益 | `159919.XSHE` | 必须仍跟踪沪深300，且满足相同准入条件 |
| 名义政府债券 | 无等价备用 | `511260.XSHG`久期不同，作为后续扩展实验，不自动替代 |
| 抗通胀实物资产 | `518800.XSHG`，然后`159934.XSHE` | 必须是实物黄金ETF，不使用黄金股ETF |
| 流动性资产 | `511990.XSHG` | 必须确认聚宽复权序列能够反映货币基金收益 |

备用切换只能由可交易性和数据可用性触发，不能由未来收益、回撤或Sharpe触发。主ETF与备用ETF仍属于同一个袖套，只占一个名额。

### 2.4 大类资产层的唯一输入

首轮大类资产层每天只能收到以下四个候选：

```text
equity       -> 510300.XSHG或其合规备用
treasury     -> 511010.XSHG
gold         -> 518880.XSHG或其合规备用
cash         -> 511880.XSHG或其合规备用
```

地域、风格和行业ETF不得绕过权益袖套直接与债券、黄金、现金排名。TopN数量、动量窗口和持仓权重不在本步骤决定。

## 三、扩展层范围

以下资产只能在四袖套核心基线通过后，以独立版本逐项加入：

1. 海外宽基ETF；
2. 港股宽基ETF；
3. 政策性金融债ETF；
4. 广义商品或农产品ETF；
5. REITs；
6. 红利、价值、成长、低波等风格ETF；
7. 行业和主题ETF。

其中，10年期国债ETF`511260.XSHG`属于债券久期扩展；它必须在5年国债核心基线通过后单独比较，不能根据哪段历史收益更高决定使用5年还是10年。

### 3.1 独立版本分支

四袖套核心基线记为`B0`。所有扩展模块首先从同一个已冻结的`B0`分叉，不允许把前一个扩展的结果作为下一个扩展的初始优势：

```text
B0：四袖套核心基线
├─ R1：B0 + 权益地域轮动
├─ S1：B0 + 权益风格轮动
├─ I1：B0 + 权益行业轮动
├─ D1：B0 + 国债久期轮动
├─ P1：B0 + 政策性金融债扩展
├─ C1：B0 + 商品扩展
└─ RE1：B0 + REITs扩展
```

每个独立版本只能改变一个候选池或一个袖套内部选择模块。动量定义、参数范围、TopN、调仓频率、成本、滑点、执行时序、风险规则和数据划分必须与`B0`保持一致。

### 3.2 各分支的唯一变化

| 版本 | 唯一允许变化 | 主要检验问题 |
|---|---|---|
| `R1`地域 | 权益袖套内部增加A股、港股、美国及其他预先指定地域宽基 | 地域选择能否改善权益代表，不增加权益在大类层的名额 |
| `S1`风格 | 权益袖套内部增加大盘、小盘、价值、成长等预先指定风格 | 风格轮动是否提供独立于宽基的净增益 |
| `I1`行业 | 权益袖套内部增加行业ETF | 行业相对强弱能否覆盖更高换手和集中风险 |
| `D1`久期 | 国债袖套内部增加不同期限国债ETF | 久期选择是否改善回撤和利率周期适应性 |
| `P1`政策性金融债 | 单独增加政策性金融债暴露 | 准主权信用和票息差是否形成独立贡献 |
| `C1`商品 | 黄金之外增加广义商品或预先指定商品类别 | 是否增加黄金之外的通胀保护，而非重复周期权益风险 |
| `RE1`REITs | 单独增加REITs袖套或子袖套 | 是否提供可验证的独立收益来源和分散效果 |

地域、风格和行业始终属于权益袖套内部。无论内部有多少ETF，权益在大类资产层仍只能产生一个代表和一个排名名额。

### 3.3 公平比较规则

1. 每个扩展版本必须同时回测`B0`和新版本的共同可用区间。
2. 新模块从2019年才有真实ETF时，`B0`也必须从同一日期开始比较，禁止用不同长度的年化指标直接比较。
3. 代理期、真实ETF期和完整研究期分别报告；扩展代理不能被描述为当时可交易业绩。
4. `B0`和扩展版本使用相同的初始资金、成本、滑点、成交约束和再平衡日期。
5. 只允许改变预注册的候选池映射，不允许同时调整动量窗口、权重或风控参数。
6. 每个失败分支永久保留代码、参数和结果，不因失败而更换ETF或删除最差年份。

### 3.4 独立扩展通过条件

扩展版本必须先满足步骤01第10.1节规定的历史研究绝对门槛，然后同时满足以下增量门槛。步骤01第10.2和10.3节的前瞻门槛只用于最终入选组合，不能用历史扩展回测代替：

1. 扣除基础成本后的Calmar相对同期`B0`提高至少0.10；
2. 同时满足以下两种改善路径之一：
   - 年化收益率相对`B0`提高至少1个百分点，最大回撤恶化不超过2个百分点；
   - 最大回撤相对`B0`降低至少2个百分点，年化收益率下降不超过1个百分点；
3. 至少60%的走步验证窗口中，扩展版本的Calmar高于同期`B0`；
4. 2倍交易成本和延迟1个交易日成交后，扩展版本相对`B0`的累计超额收益仍为正；
5. 增量收益不能主要依赖单一ETF、单一年份或单一市场阶段；
6. 新模块造成的换手率、集中度和最长水下时间必须完整报告。

任一条件未通过，该独立扩展记为失败，不进入组合阶段。上述增量门槛只能在看到结果前修改；开始任何扩展回测后即冻结。

### 3.5 组合阶段

只有独立版本通过后，模块才有资格进入组合候选。为避免穷举所有排列组合，组合顺序预先固定为：

```text
地域 -> 风格 -> 行业 -> 国债久期 -> 政策性金融债 -> 商品 -> REITs
```

- 未通过独立验证的模块直接跳过，不能用组合效果掩盖其独立失败。
- 每加入一个模块，都必须与“加入前的上一组合版本”重新进行单变量增量比较，并满足本节3.4的门槛。
- 组合后仍保持分层结构：权益内部模块的总权重不得突破大类资产层分配给权益的权重。
- 不测试全部排列组合，也不根据历史最好结果改变上述加入顺序。
- 最终组合仍需完整通过步骤09的走步验证和步骤10的前瞻测试，历史扩展通过不等于最终策略通过。

## 四、历史代理选择顺序

当ETF历史不足时，只允许使用聚宽内部可获得的指数、现货或连续合约数据作为训练代理。每个袖套按以下顺序选择：

1. 经济含义与ETF底层暴露一致；
2. 总收益、财富或含票息口径优先于价格指数；
3. 数据历史尽可能长且字段连续；
4. 人民币计价优先，避免不必要的汇率和跨时区处理；
5. 能映射到境内证券账户可交易ETF；
6. 选择过程不使用候选代理的历史收益、Sharpe、回撤或Calmar。

若聚宽只能提供价格指数，允许作为暂定代理，但必须标记“未包含分红或票息”，不得与总收益口径混称。期货连续序列必须明确主力切换和展期口径；无法说明时不得进入核心基线。

## 五、训练起点规则

1. 先在聚宽内分别确定四类袖套的最早可靠日期。
2. 长历史代理训练起点取四类袖套最早可靠日期中的最晚者。
3. 起点必须由统一算法生成，不能根据回测曲线移动。
4. 训练区间应尽量覆盖2008年金融危机；若聚宽某个必要袖套无法覆盖，则如实记录实际起点，不用外部数据强行补齐。
5. 代理期只用于研究动量规律和参数稳定性，不模拟当时已能买入ETF。
6. 真实ETF区间从四个袖套都至少存在一只合格ETF的首个共同调仓日开始。

## 六、ETF候选池生成规则

### 6.1 聚宽证券范围

- 首轮主白名单固定为`510300.XSHG`、`511010.XSHG`、`518880.XSHG`、`511880.XSHG`。
- 备用白名单固定为`159919.XSHE`、`518800.XSHG`、`159934.XSHE`、`511990.XSHG`。
- 使用`get_all_securities(['etf', 'fund'], date=T)`或分别查询两类，再按冻结白名单筛选第T日存在的产品。聚宽可能将货币ETF归入`fund`而非`etf`，不能只按单一类型排除`511880.XSHG`。
- 使用聚宽返回的`start_date`和`end_date`判断上市、退市和清盘状态。
- 已退市或已清盘ETF仍保留在其真实存在的历史区间，不能只保留当前存续基金。
- 在第一次正式回测前建立“代码、名称、资产袖套、跟踪标的、允许/排除理由”白名单并冻结。

### 6.2 动态准入

ETF在第T日同时满足以下条件，才能用于第T日收盘信号并最早于T+1开盘交易：

1. 上市已满252个A股交易日；
2. 最近60个交易日行情字段完整；
3. 最近60个交易日平均成交额`money`不低于5000万元；
4. 第T日未退市，且聚宽数据不存在停牌或不可交易标记；
5. 属于本步骤允许的资产类别；
6. 非杠杆、非反向、非分级基金。

上市交易日数量使用`get_trade_days`计算，不能用自然日近似。成交额窗口只使用第T日及以前的数据。

### 6.3 袖套内去重

- 动量先在四个资产袖套之间排名，再映射到具体ETF。
- 跟踪同一指数或高度相似指数的多只ETF只能代表一个袖套，不能重复占据TopN名额。
- 袖套内优先选择历史时点映射最准确、过去跟踪偏差较小、过去60日成交额较高、上市较早的ETF。
- 费用只有在聚宽内能够取得带生效日期的历史费率时才参与历史排序；禁止用当前费率回填过去。
- 所有排序指标只使用第T日及以前的数据，最终再以证券代码作为确定性平局规则。

## 七、聚宽数据合同

### 7.1 元数据和交易日历

| 用途 | 聚宽接口 | 必需内容 |
|---|---|---|
| 历史证券范围 | `get_all_securities(['etf', 'fund'], date=T)` | 代码、`start_date`、`end_date`、平台证券类型 |
| A股交易日历 | `get_trade_days` | 上市交易日计数、调仓日、T+1执行日 |

### 7.2 ETF行情

使用`get_price`获取日频数据：

- 成交与记账价格：`fq='none'`，字段至少包含`open/high/low/close/volume/money`；
- 动量信号价格：在每个历史时点以`end_date=T`请求`fq='pre'`的连续价格；
- 不得一次取得未来日期后再把全样本前复权序列切回过去；
- 第T日信号只使用第T日收盘后已知的数据，成交价最早为T+1开盘价；
- 停牌、无开盘价、涨跌停和缺失值必须使用不同状态处理。

### 7.3 代理数据

每条代理序列至少记录：

- 聚宽证券代码；
- 资产袖套；
- 数据类型：指数、现货、连续合约或现金；
- 收益口径：价格、全收益、财富、票息再投资或展期；
- 币种；
- 最早可用日期；
- 信息可得时间；
- 对应ETF及切换条件。

## 八、未来数据防护

1. 所有查询显式设置`end_date=T`，不依赖平台默认当前日期。
2. ETF准入只使用T日及以前的上市时间、成交额、行情完整性和跟踪差异。
3. 跨境或海外扩展资产必须单独定义时区和信息滞后；未定义前不得加入核心基线。
4. 指数成分、ETF池和证券存续状态均按历史日期查询，禁止使用当前列表回填早期历史。
5. 代理切换到ETF的日期由“上市满252个交易日且满足60日流动性”的规则自动生成。
