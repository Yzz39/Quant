## 本步骤目标

证明以下链路在代码和聚宽平台中都按研究协议工作：

```text
第T日收盘后生成信号
-> 第T+1交易日开盘后执行
-> 先卖出释放现金
-> 再按实际可用现金买入
-> 扣除滑点和佣金
-> 更新持仓、现金和净值
-> 未成交订单有限重试且不重复成交
```

步骤03只回答“引擎算得是否正确”。即使所有测试通过，也不能说明ETF动量策略能够赚钱。

## 一、验证边界

### 1.1 本步骤验证

- 信号日期和成交日期的严格滞后；
- 调仓日与非调仓日订单边界；
- 未复权成交价格、滑点、佣金和最低收费；
- 100份整数交易和资金不足；
- 多资产先卖后买；
- 缺失开盘价、停牌、涨跌停方向限制和失败重试；
- 分红、拆分、持仓市值、现金和总资产；
- 聚宽订单、成交、持仓和账户日志的可追踪性；
- 步骤02四个核心ETF在聚宽的元数据和日线字段可用性。

### 1.2 本步骤不验证

- 哪个动量周期最好；
- Top1或TopN是否更优；
- 绝对动量、止损和波动率控制；
- 年化收益、最大回撤和最终目标；
- 地域、风格、行业和其他扩展池。

上述问题在步骤04以后验证，禁止提前混入本步骤。

## 四、本地合成数据验证

### 4.1 参考实现原则

- 信号提交当天不能成交；
- 首个执行日把目标权重转换成固定整手目标数量；
- 成功成交的数量不会在重试日重复提交；
- 缺失开盘价不得用当日收盘价或未来开盘价替代；
- 失败订单保留原信号意图，最多尝试3个交易日；
- 分红进入现金，拆分调整份额，净值按持仓与最新合法价格计算；
- 非调仓日不为了恢复权重而隐式交易。

## 五、聚宽平台探针

### 5.1 运行设置

将`step03_joinquant_engine_probe.py`粘贴到聚宽策略编辑器并使用以下设置：

| 设置 | 要求 |
|---|---|
| 回测频率 | 分钟 |
| 初始资金 | 100,000元 |
| 回测起点 | 不早于四个核心ETF均已上市的日期，建议先用2016-01-04 |
| 回测长度 | 至少12个A股交易日 |
| 基准 | `000300.XSHG` |
| 复权模式 | `use_real_price=True` |
| 未来数据防护 | `avoid_future_data=True` |

探针使用固定日期计划，不使用动量信号：

```text
第1个交易日收盘：目标510300为50%
第2个交易日开盘后：执行买入
第4个交易日收盘：目标518880为50%
第5个交易日开盘卖510300，09:35后买518880
第7个交易日收盘：目标空仓
第8个交易日开盘：卖出518880
```

这种固定计划只验证事件顺序和记账，不产生策略收益结论。

## 八、已知边界

- 本地参考实现用合成开盘价直接撮合，不模拟真实盘口队列和部分成交概率；
- 聚宽探针验证平台行为，但无法人为保证测试区间恰好发生停牌或涨跌停；这些异常由本地合成测试覆盖，后续遇到真实案例再抽查；
- 聚宽文档和平台订单状态命名可能存在版本差异，以实际回测日志为准并记录；
- 步骤04的M2无效运行发现：2016-01-04目标买入2200份`511010.XSHG`仅成交717份，代码却立即判定完成；2018-09-04部分卖出后剩余22份，代码跳过清仓并在第三次尝试后让信号过期。两者都会改变实际仓位和绩效，故步骤03重新打开；
- 首次平台运行发现`UserTrade`没有文档所列`side`属性；v0.3改为从关联订单推导方向，并兼容读取成交金额；
- 第二次平台日志的交易时序、4笔成交和账户恒等式通过，但`511880.XSHG`未出现在单独`etf`元数据查询中；v0.4同时查询`etf`与`fund`并输出撮合参考价；
- v0.5复核确认`511880.XSHG`属于聚宽`fund/mmf`分类；4笔成交相对0.05%理论滑点价的误差均在0.001元最小报价单位以内；
- 本步骤通过只证明工程链路正确，不证明动量趋势确认正确。
